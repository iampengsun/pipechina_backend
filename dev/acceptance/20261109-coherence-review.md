# 模块一致性与可维护性核查

日期：2026-11-09。范围为现有后端模块衔接、接口契约、构建更新与文档一致性。

## 发现与处理

| 问题 | 修整结果 |
|---|---|
| 架构测试硬编码早期七个模块，漏掉隐患和质量改进 | 自动发现全部九个模块；检查跨层依赖和跨模块API引用。只要求实际使用的分层，不强制创建空任务或仓储文件 |
| 质量改进使用平铺目录，MCP反向导入HTTP路由中的转换函数 | 归入`api/application/domain`；MCP和HTTP共用应用服务与领域响应模型 |
| 会议知识发布直接调用知识HTTP路由函数 | 公共任务创建移入`knowledge/application/jobs.py`，两个模块通过应用服务协作，不依赖HTTP Request |
| 隐患附件借用工单业务入参，校验逻辑重复且过期策略不一致 | 附件契约、过期/元数据/摘要校验归入`shared/media`；各模块保留自己的权限、归属检查与审计。缺少有效期的上传也按失效处理 |
| 新增工单接口按数据库列反射响应，质量/记忆接口重复维护字段清单 | 使用明确的响应模型；工单整改、验收、提醒在OpenAPI中可见，不再自动暴露新增数据库列 |
| 只读容器命令也会生成或重写`.env` | 配置生成仅发生在启动/重置；查询、日志、停止操作不再写入配置 |
| 离线更新仅覆盖源码，旧模块和字节码可能残留 | 核对依赖后完整替换源码目录、排除字节码；检查并保留非root用户与启动命令。实际容器已确认旧质量文件不存在 |
| 模板空层、旧产品服务名与补丁式文档追加 | 删除无实现的隐患基础设施包；模型服务统一PipeChina名称；README、部署及服务说明改为当前状态，历史验收单独保存 |

既有教学注释和组件基础说明保留，尤其是`evaluation.py`的逐点解释。清理针对重复映射、隐式反射、没有实现的模板目录和不清楚的依赖边界。

## 契约与数据

- 原有HTTP路径保留；隐患附件列表补充MIME类型和文件大小。分页及评测类型参数统一使用422校验。
- 数据库表、状态机和审批职责不变，无新增迁移。
- 领域中真实不同的流程保留，例如隐患验收与工单关闭、匿名说话人标签与身份认证；未为目录整齐合并业务含义不同的概念。
- 离线更新适用于本项目无自定义ENTRYPOINT的运行镜像；自定义入口提前拒绝，交由Dockerfile构建。
