## 23 RAG、分段、查询改写、混合检索、引用与拒答

RAG是检索增强生成：回答前先从有权访问的资料中找证据，再把证据交给模型。它不等于训练模型，也不能保证模型永远正确。

文档通常太长，系统先按版面或结构拆成片段，保存原文定位及版本。片段太小可能丢失条件，太大可能让无关文字占满上下文。查询改写产生少量检索表达，必须保留型号、日期和否定条件，不能悄悄把原问题改成另一件事。

```text
文档上传与审核 → 解析、分段、建立索引 → 发布有效快照
问题 → 当前权限与版本过滤 → 多路召回 → 融合/重排
→ 证据与定位 → 生成候选回答 → 引用检查或拒答
```

混合检索结合全文、向量等不同召回；图检索沿已保存关系取得邻近证据。引用要能回到实际片段、文档版本和位置；一个存在的引用ID不一定支持当前结论，还需核对原文语义。

**基本使用。** 本项目先通过知识模块上传、处理和发布资料，再用查询接口取证。没有资料、资料已撤回、证据不足或条件不适用时，应保留未知或拒答。调查角色通过`search_knowledge`使用同一检索服务，而不是另建一套RAG。

主流程见[retrieval.py](../../app/modules/knowledge/application/retrieval.py)、[知识接口](../../app/modules/knowledge/api/router.py)和[第8章](../第08章_企业知识与RAG模块开发.md)。

## 24 Elasticsearch、倒排索引、BM25与查询DSL

全文检索适合找出现了哪些词、编号或型号的资料。倒排索引从词指向包含它的文档，避免每次从头扫描全部正文。Elasticsearch中索引组织文档，mapping定义字段类型，分析器决定如何分词。

BM25是词项相关性评分方法，会综合词在当前文档中的出现情况、词的区分度及文档长度等因素。分数用于排序，不是“答案正确概率”。中文分词、设备编号和完全匹配字段需要分别考虑。

下面是ES查询DSL的教学片段，只表达查询结构，`learning`前缀表示独立学习资料：

```json
{
  "query": {
    "bool": {
      "must": [{"match": {"text": "阀门 泄漏"}}],
      "filter": [{"term": {"generation": "learning"}}]
    }
  },
  "size": 5
}
```

`must`参与匹配与相关性，`filter`约束范围，`size`限制返回数量。正式项目还必须限制可见版本和当前索引代际；不能把教学片段作为完整授权查询。

**在本项目中。** [HTTP索引适配器](../../app/infrastructure/knowledge/http.py)构造实际mapping和查询，业务不能自行绕过端口拼查询。先读[第8章](../第08章_企业知识与RAG模块开发.md)的ES练习，再看检索跟踪中全文召回了什么。

## 25 Qdrant、向量索引、相似度与过滤

向量检索把文本变成一串数值，再按数值方向或距离寻找相近片段。Qdrant保存向量及其关联属性，称为向量数据库。向量相近表示模型认为语义相似，不保证规范适用或事实一致。

以余弦相似度为例，它比较向量夹角。下面是只解释计算的二维例子，不是项目实际Embedding：

```python
from math import sqrt

a, b = [1.0, 0.0], [1.0, 1.0]
dot = sum(x * y for x, y in zip(a, b))
cosine = dot / (sqrt(sum(x * x for x in a)) * sqrt(sum(y * y for y in b)))
assert 0.70 < cosine < 0.71
```

Collection保存一组维度和距离配置兼容的向量；Point保存某条记录的向量、ID和payload属性。过滤条件限制版本、代际和访问范围，不能只取全局最相似结果后再补一个授权说明。

**基本使用。** 对片段用同一Embedding模型生成向量并写入代际Collection；查询时把问题编码成同维度向量，带上当前可见版本过滤。模型或维度变更需要重新建立兼容索引。

实现见[QdrantIndex](../../app/infrastructure/knowledge/http.py)与[知识端口](../../app/ports/knowledge.py)。项目未要求业务层安装Qdrant Python SDK，而是通过端口与HTTP适配器调用。

## 26 Neo4j、属性图、Cypher、关系投影与Outbox

Neo4j把数据表达为节点、关系和属性。节点可表示设备或事件，关系可表示“设备关联事件”；属性保存编号、组织和版本。关系有方向，但图中相连不自动表示因果。

Cypher是图查询语言，括号表示节点，箭头表示关系。下面只在Neo4j查询界面或独立学习图执行，不创建正式业务节点：

```cypher
MATCH (n)
RETURN labels(n) AS labels, count(*) AS amount
ORDER BY amount DESC
LIMIT 10;
```

本项目有知识关系图和业务关系投影。知识图用于检索原文中的关系证据；业务图连接设备身份、事件、工单、验收和知识引用。PostgreSQL中的人工确认记录是正式来源，Neo4j投影用于关系查询。

**基本使用。** 通过业务接口登记设备与关联，再让后台读取图谱Outbox更新投影；用证据链、复发或影响复核接口查询。不要在Neo4j里直接改投影来冒充业务确认，否则主库和图会不一致。

投影可能暂时落后，因此结果带同步状态、范围和验证信息；查到路径后仍要回主库检查版本与权限。代码见[业务图端口](../../app/ports/business_graph.py)、[投影](../../app/modules/operational_graph/application/projection.py)和[查询](../../app/modules/operational_graph/application/queries.py)。入门练习见第8章，业务应用见[第13章](../第13章_业务图谱设备身份与变更影响复核.md)。

## 27 Embedding、BGE-M3与Sentence Transformers

Embedding模型把文本编码为定长数值向量，希望语义相关的文本在向量空间接近。它负责表示，不直接生成业务答案。模型、revision、维度及归一化方式共同影响结果，不能只看模型名称相同。

BGE-M3是本地知识运行时配置的文本表示模型；Sentence Transformers提供模型加载与编码接口。项目将向量归一化后交给Qdrant，并保存模型与索引代际信息。

**基本请求形状。** 知识运行时的`POST /v1/embeddings`接收：

```json
{"model": "BAAI/bge-m3", "input": ["阀门密封渗漏", "设备编号V-1"]}
```

返回结果按输入索引对应向量；实际模型名须与服务配置一致，认证也按知识运行时配置提供。这个请求属于CPU模型服务，不是业务API的模型训练入口。

代码中的`encode(..., normalize_embeddings=True)`执行编码和归一化。模型首次加载可能需要权重，服务就绪与本条文本表示是否适合业务仍是不同验证问题。实现见[knowledge_runtime/main.py](../../services/knowledge_runtime/main.py)及[HTTPEmbedding](../../app/infrastructure/knowledge/http.py)。

## 28 Reranker、CrossEncoder、BGE Reranker与RRF

召回先找一批可能相关的材料，Reranker再对“问题、候选片段”逐对评分。CrossEncoder让模型同时读取二者，通常比仅比较两个预先编码向量更细致，但每对都要计算，所以适合对有限候选重排。

项目使用BGE Reranker。CPU服务的`POST /v1/rerank`请求形状为：

```json
{
  "model": "BAAI/bge-reranker-v2-m3",
  "query": "阀门泄漏如何核查",
  "documents": ["先核对压力和密封部位", "办公用品领用流程"]
}
```

模型名、认证和服务可用性仍须与配置一致。重排分数属于相关性信号，不是现场结论，也不能恢复已被授权过滤排除的材料。

RRF是按排名融合多路召回的方法。每路中某条证据排得越靠前，贡献越大；项目使用`1/(60 + rank + 1)`，其中`rank`从0开始。同一证据被多路找到时累加贡献。RRF不直接比较全文和向量的原始分数，和使用模型的Reranker是不同环节。

**基本阅读顺序。** 在[retrieval.py](../../app/modules/knowledge/application/retrieval.py)先看多路召回与RRF，再看重排；服务端模型调用见[运行时](../../services/knowledge_runtime/main.py)。

## 29 Docling、OCR、RapidOCR、ONNX Runtime与pypdf

文档解析先把文件变成带结构和定位的内容。文本PDF可能已有可读取文字，扫描PDF只有页面图像，需要OCR；OCR是从图像识别文字，不等于理解规程是否适用。

Docling负责文档转换和版面结构；RapidOCR承担OCR能力；ONNX Runtime执行ONNX格式的推理模型。它们分工不同：转换器决定读哪个区域，识别器产生文字，推理运行时执行模型计算。

```text
文件 → 页面与版面解析 → 必要时OCR → 文本/表格及定位
→ 人工纠错与校验 → 分段与索引 → 审核发布
```

识别错误会影响型号、数字和否定条件，不能因为程序成功解析就自动发布。表格跨页、页眉和阅读顺序也需要保留可回查定位。

**最小开发侧检查。** pypdf可以检查已有PDF文本，下面只定义检查函数，不自动读取文件：

```python
from pypdf import PdfReader


def first_page_text(path):
    reader = PdfReader(path)
    return reader.pages[0].extract_text() or ""
```

pypdf属于本项目开发侧验证工具，不能把它当作完整OCR流程。生产解析在独立CPU知识服务中执行，见[convert.py](../../services/knowledge_runtime/convert.py)与[解析任务接口](../../services/knowledge_runtime/main.py)。业务侧校验与纠错见[第8章](../第08章_企业知识与RAG模块开发.md)。

## 30 Whisper、faster-whisper、VAD、热词与说话人处理

ASR把音频转成文字。Whisper large-v3是模型，faster-whisper是项目使用的推理实现；二者不能和业务中的人工转写版本混为一谈。VAD判断哪些时间段有语音，热词给识别器提供领域提示，均不能保证编号或人名一定识别正确。

说话人分离回答“哪些片段可能由同一个人说”，不是验证真实身份。本项目用SpeechBrain产生说话人向量，再按余弦距离与层次聚类归组，得到`SPEAKER_00`等标签。SciPy负责聚类算法，标签与姓名的关系仍须人工核对。

PyAV/FFmpeg承担音频容器和编解码相关能力；采样率表示每秒采样数，和文件大小或语音内容不是同一概念。项目说话人处理将音频按16kHz解释，业务片段时间使用毫秒。

**基本使用。** 上传并验证录音，再提交转写Job，读取分段结果、校订文字和说话人映射。不能仅将文件扩展名改成支持格式，也不能用健康检查代替识别效果检验。

```text
原始文件 → 解码与采样 → VAD/识别 → 时间片段与文字
→ 说话人向量和聚类标签 → 人工校订 → 确认转写版本
```

实现见[ASR服务](../../services/asr/app.py)、[说话人处理](../../services/asr/diarization.py)。沿[第3章](../第03章_调度交接班记录模块开发.md)练习转写，沿[第9章](../第09章_会议录音转写与知识发布.md)学习会议标签与姓名映射。

## 31 MiniCPM-V、Transformers、PyTorch及模型运行组件

视觉语言模型同时接收图像与文字，产生候选描述或结构化结果。本项目MiniCPM-V用于图片场景与候选隐患分析；它不能从看不见的部位证明设备安全，也不自动确认隐患。

| 组件 | 在运行中的基本作用 |
|---|---|
| Transformers | 加载模型、处理器并执行生成流程 |
| PyTorch | 张量运算与模型推理；本项目CPU模型服务独立部署 |
| torchvision / torchaudio | 配套图像、音频能力与依赖，具体调用以服务代码为准 |
| Pillow | 打开图像、处理方向、尺寸和像素格式 |
| Accelerate | 支持模型加载及设备分配等运行能力 |
| safetensors | 模型权重的一种文件格式和加载支持 |
| sentencepiece | 文本分词相关支持，将文字转换为模型可处理的单元 |
| lm-format-enforcer | 在支持的生成路径中约束结构化输出形状 |

张量可以理解为多维数值数组。dtype规定数值表示和精度，device规定计算位置；这些选择影响内存、速度和兼容性，不能在CPU服务里照抄GPU配置。

**基本使用。** 项目从已验证上传的图片创建分析任务，服务先判断场景，再形成候选。结构化输出约束和Pydantic校验能检查格式，无法证明图像语义判断正确。需要人员复核原图、候选描述和置信度。

模型加载锁定revision，服务中可看到`AutoProcessor.from_pretrained`与`AutoModelForImageTextToText.from_pretrained`。不要在主后端进程另加载同一大模型。实现见[vision/app.py](../../services/vision/app.py)、[输出计量](../../services/vision/token_output.py)和[第6章](../第06章_巡检图片分析与隐患上报模块开发.md)。

## 32 python-docx、ReportLab与DOCX/PDF导出

DOCX保存可编辑的文档结构与样式；PDF更强调固定版面。python-docx用于构造Word段落、表格和样式，ReportLab用于生成PDF。导出成功只证明文件可产生，内容仍需核对来源和审核状态。

下面是独立学习目录中的最小Word示例，会写入指定教学文件：

```python
from docx import Document

# 仅在独立学习目录执行此示例。
document = Document()
document.add_heading("软件教学示例", level=1)
document.add_paragraph("本段不代表真实生产报告。")
document.save("learning-report.docx")
```

PDF示例同样只写教学文件：

```python
from reportlab.pdfgen.canvas import Canvas

canvas = Canvas("learning-report.pdf")
canvas.drawString(72, 760, "Software learning example")
canvas.save()
```

中文PDF还需注册可用中文字体，不能认为英文示例直接替换汉字就一定正确。长文本换行、跨页表格、页边距和图片尺寸也需要检查。

**在本项目中。** [报告服务](../../app/modules/report/application/service.py)和[任务](../../app/modules/report/application/tasks.py)固定报告版本、生成对象并提供受授权下载。导出不改变业务审批状态。先读[第7章](../第07章_生产运行日报与事件复盘模块开发.md)，再观察导出Job与最终文件。
