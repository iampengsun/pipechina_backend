# 第7章：生产报告与事件复盘

DOCX是可编辑的Word文档格式，PDF更强调固定版面；python-docx与ReportLab分别生成相关文件。报告业务日期依赖时区，版本快照说明正文依据哪些资料；后台导出只生成对象，不替代审核发布。

相关基础：[Word/PDF基本导出](基础知识/05_检索文档与多模态.md#t32)、[时区与来源快照](基础知识/07_部署监控与工程验证.md#t41)、[后台任务](基础知识/03_任务权限与文件存储.md#t08)、[对象存储与授权下载](基础知识/03_任务权限与文件存储.md#t14)。

## 7.1 报告是来源整理的结果

生产日报按日期和组织整理运行情况；事件复盘围绕特定范围汇总过程、判断和处理结果。报告正文由模型或人工形成，不能替代来源中的确认状态、工单验收或原文证据。

报告记录与正文版本分开：主记录保存类型、业务日期、时区和发布指针，版本保存某次生成或人工编辑的内容。旧版本保留，发布指向明确的一版。

## 7.2 创建范围与时间边界

```json
{
  "report_type": "daily",
  "business_date": "2026-11-10",
  "timezone": "Asia/Shanghai",
  "scope_filter": {}
}
```

`report_type`支持`daily`与`incident_review`。日期用于业务统计，时区决定这一天的起止时刻；不能将北京时间的一天直接按UTC零点截取。

`scope_filter`由当前用例解释，不是任意SQL过滤器。来源选择仍检查调用者权限、组织范围和业务状态，空过滤条件也不会授予全局读取权。

## 7.3 生成、编辑、审核与发布

```text
建立报告 → 固定来源范围 → 提交生成任务 → 保存草稿版本
→ 人工核对与编辑 → 审核 → 发布指定版本 → 导出
```

应用服务筛选已确认交接、事件、巡检等可用来源，保存来源快照后调用文字模型。相同范围上的并发生成与旧任务提交受当前Job绑定、租约和提交检查约束。

编辑创建新版本；审核与发布各自执行业务规则。已经生成的草稿不会因为以后出现新记录自动变成“包含所有最新信息”的报告；需要明确重新生成或修订。

撤回保留历史。使用发布版本时还要检查当前可见范围，不能借报告快照绕过来源权限变化。

## 7.4 正文怎样核对

阅读报告时，将每一项重要结论对应到来源：事件是哪一版、是否确认；措施是建议还是已执行；工单是resolved还是经过独立验收的closed；指标是否有单位、时间和判定依据。

缺少来源时应标记待核实，不把模型归纳补写成现场事实。复盘中的因果说明同样需要证据，不能仅凭两项记录在时间上接近就确认原因。

## 7.5 异步导出与定时任务

导出支持DOCX和PDF，经导出Job生成对象，再使用受授权的下载入口取得文件。创建导出请求不等于文件已经存在；生成失败先检查报告版本、字体、文件服务和任务记录。

Beat可以周期触发日报任务，任务身份和组织范围由服务端确定。定时执行不会自动绕过人工审核与发布规则，也不代表报告内容经过专家效果验证。
