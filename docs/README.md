# 项目文档

本套文档按业务流程介绍后端实现。项目以REST API和MCP提供业务能力，不包含业务前端；数据库迁移为`0001 → 0002_agent_tasks → 0003_station_locations`，共有85张应用表，完整本机环境由20项项目专用Compose服务组成。

## 三个组件的学习入口

RabbitMQ先看第2章的生产者、队列、消费者、ACK和Outbox；Elasticsearch先看第8章的索引、mapping、分词和DSL；Neo4j先看第8章的节点、关系与Cypher，再看第13章的业务应用。教学练习使用单独的索引名或标签，不写入正式业务资料。

## 贯穿项目的业务链

```text
交接记录/人工文本 → 候选事件 → 人工确认 → 多角色调查 → 人工审核 → 工单
巡检图片 → 视觉候选 → 人工复核 → 事件/隐患 → 措施 → 实测 → 独立验收
会议 → 转写校订 → 确认纪要 → 知识审核发布 → RAG取证
已确认观察 → 短期调查上下文；关闭工单 → 经验草稿 → 独立审核 → 长期经验
评测 → 确认问题与措施 → 实施 → 新评测运行 → 前后指标 → 独立验收
业务引用 → 图谱投影 → 证据路径/变更复核/重复异常
```

原始记录、模型候选、人工确认和正式发布分别保存。判断一项内容能否使用，要同时检查状态、版本、有效期和权限。

## 使用约定

命令从仓库根目录执行。REST默认前缀为`/api/v1`，MCP入口为`/mcp/`，完整请求字段见运行中的`/openapi.json`。各章接口表列出当前路径和处理函数，代码链接可继续定位实现。

异步请求返回受理信息后，须查询Job或业务运行结果，不能把HTTP 202当作任务完成。版本冲突通常返回409；应重新读取记录并核对变化，再决定是否重试。

测试数据库必须与业务库分离：测试会删除目标库的`public` Schema。`.env`、真实密钥和JWT不纳入版本控制。初始化、清理和恢复命令详见第2章及[基础设施说明](../infra/README.md)。
