# 第3章：调度交接班记录

ASR把音频转成文字，VAD判断哪些片段有语音，说话人分离按声音特征生成匿名标签；这些结果仍需人工校订。S3对象存储保存文件字节，数据库保存文件与业务的关系；Celery在后台运行识别，API先返回受理信息。

相关基础：[语音与说话人处理](基础知识/05_检索文档与多模态.md#t30)、[上传与对象存储](基础知识/03_任务权限与文件存储.md#t14)、[后台任务](基础知识/03_任务权限与文件存储.md#t08)、[输入校验](基础知识/01_Web接口与配置.md#t03)。

## 3.1 先理解录音、转写与摘要

录音是原始字节；转写是模型或人工形成的文字版本；摘要是依据某个转写版本整理的结构化内容。三者分别保存，人员可以追查一句摘要来自哪段文字，而不必用新内容覆盖旧记录。

ASR负责语音识别，输出全文和带时间范围的片段。`speaker_label`表示系统区分出的说话人标签，不天然等于真实姓名。摘要模型再从文字中整理交接重点、异常和待办；这些结果须经人工核对后确认。

## 3.2 数据对象与代码入口

| 对象 | 作用 |
|---|---|
| `AudioRecord` | 班次、文件、上传状态、业务状态及当前版本指针 |
| `AudioTranscriptVersion` | 一次转写或人工校订的全文与来源 |
| 转写片段 | 起止毫秒、文字和说话人标签 |
| `HandoverSummaryVersion` | 指向转写来源的摘要版本 |
| `ManualOperationRecord`及版本 | 人工记录，也用于固化临时事件抽取文本 |

先读[schemas.py](../app/modules/handover/domain/schemas.py)了解字段，再看[router.py](../app/modules/handover/api/router.py)如何进入[service.py](../app/modules/handover/application/service.py)。后台任务位于[tasks.py](../app/modules/handover/application/tasks.py)，具体语音服务在[services/asr](../services/asr)。

## 3.3 完整业务流程

```text
登记录音 → 获得上传授权 → 传输文件 → 服务端验证
→ 提交转写任务 → 读取转写结果 → 人工校订
→ 生成摘要 → 人工校订摘要 → 确认交接记录
```

上传状态与业务状态分开。例如文件已经验证，不代表已经转写；转写完成，也不代表摘要已经确认。业务状态会经历`transcribed`、`summary_ready`等阶段，确认后为`confirmed`，以当前响应为准。

登记请求示例：

```json
{
  "shift_date": "2026-11-10",
  "shift_code": "night",
  "filename": "handover.m4a",
  "size_bytes": 1048576,
  "mime_type": "audio/mp4"
}
```

返回内容包含录音信息与上传授权。应把实际文件传到授权指定位置，再调用上传完成接口；不能用上面示例中的大小替代真实文件长度。校验失败时先核对文件、对象键和授权，而不是直接触发转写。

## 3.4 转写任务怎样执行

API创建Job并通过Outbox投递。Worker取得执行身份与租约，读取已验证文件，调用ASR，再保存转写版本和片段。数据库提交前仍检查取消、当前绑定、录音是否删除或已经确认等条件。

任务返回202后，应查询Job和录音当前版本。若失败，结合Job事件、错误码及Worker日志定位存储、解码、ASR或提交阶段；重试走任务接口，不手改状态。

ASR服务承担音频解码、识别和说话人分离。服务能够响应健康检查只表示进程或组件就绪，不能证明当前录音识别准确。验证识别效果需要对应录音、人工文字和说话人标注。

## 3.5 人工校订与摘要来源

转写校订输入包含`full_text`和`segments`。每个片段要求非负起点、终点晚于起点，并按时间排序且不重叠。时间单位为毫秒，不能混用秒。

摘要校订可明确指定`transcript_version_id`及`source_segment_ids`，来源片段不能重复，也须属于指定转写。这样可以解释摘要引用的是哪次校订后的内容。

修改转写后，旧摘要仍保留历史意义，但不能自动充当新转写的确认结果。确认交接记录前，应核对当前转写、摘要及来源关系。已确认录音的后续变更受服务端业务规则限制，不能绕过确认状态直接重跑覆盖。

## 3.6 人工记录如何衔接事件

人工运行记录保存当前版本指针和正文历史。事件抽取指定记录与版本，后台按固定版本读取，避免任务排队后正文被改成另一份内容。

临时`raw_text`也会先固化为人工记录及版本。录音转写抽取则使用`audio_transcript`来源，保存录音ID与转写版本ID。详细流程见[第4章](第04章_生产运行事件抽取与归档模块开发.md)。

## 3.7 权限与验证

上传、读取、处理、编辑和确认使用相应业务权限与数据范围。任务执行者不是无限权限的系统账户，排队期间撤权会影响后续执行。

用[交接测试](../tests/test_handover_flow.py)观察完整流程，用[媒体验证测试](../tests/test_media_security.py)检查异常文件和授权边界。练习时应分别验证：上传不完整、ASR失败、人工修改、摘要来源不匹配、重复任务及确认后旧任务提交。
