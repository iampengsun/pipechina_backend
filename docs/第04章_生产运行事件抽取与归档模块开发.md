# 第4章：生产事件抽取与归档

结构化抽取把文本整理成有明确字段的候选对象。Pydantic校验字段形状，来源版本说明候选依据哪份文字；权限、状态和人工确认决定它何时可成为正式事件。版本快照保留历史，幂等处理防止同一请求重试产生重复业务结果。

相关基础：[结构化输入输出](基础知识/01_Web接口与配置.md#t03)、[幂等与任务执行](基础知识/03_任务权限与文件存储.md#t11)、[数据范围](基础知识/03_任务权限与文件存储.md#t13)、[版本与审计](基础知识/07_部署监控与工程验证.md#t41)。

## 4.1 候选事件与正式事件

事件抽取把交接文字或人工记录整理为有标题、描述、类别和严重程度的候选。模型给出的结构化JSON仍可能包含遗漏或误判；通过Schema校验，只能说明输出形状合法。

人员核对正文和原文证据后确认，事件才成为正式业务事实。修改正式事件会形成新版本并回到候选状态，旧调查和审核不能自动沿用到新版本。

## 4.2 来源必须可以重放

| 来源类型 | 输入 | 服务端固定的内容 |
|---|---|---|
| `raw_text` | 临时正文 | 先创建人工记录及版本 |
| `manual_operation` | 人工记录ID，可指定版本 | 属于该记录的正文版本 |
| `audio_transcript` | 转写版本ID | 对应录音和这次转写全文 |

后台任务读取已保存的来源版本，不依赖HTTP请求内存，也不临时选择“最新正文”。指定的版本必须确实属于相应主记录，读取来源还须符合权限与组织范围。

## 4.3 数据对象与执行过程

`ProductionEvent`保存事件主信息、业务状态与当前版本；`ProductionEventVersion`保存每次正文和结构化内容；`EventSourceLink`记录来源主键、版本、原文证据和定位。

```text
校验来源 → 固化版本 → 创建Job/Outbox → Worker读取固定正文
→ 模型抽取 → 校验候选 → 保存事件、版本及来源关联
→ 人工修改或确认
```

实现从[API](../app/modules/operation_event/api/router.py)进入[应用服务](../app/modules/operation_event/application/service.py)，实体和字段见[models.py](../app/modules/operation_event/domain/models.py)与[schemas.py](../app/modules/operation_event/domain/schemas.py)。

## 4.4 提交与读取本次结果

临时文本请求示例：

```json
{
  "source_type": "raw_text",
  "raw_text": "交班记录：二号阀门发现轻微渗漏，已设置警戒并通知维检。"
}
```

将它提交到`POST /api/v1/event-extractions`。正常异步环境先受理任务；根据返回的Job ID查询状态，再用`GET /api/v1/event-extractions/{job_id}/results`读取该次产物。一次输入可能产生多个候选，也可能没有足够信息形成事件。

不要按事件列表的最新一条猜测本次抽取结果。Job与结果的明确关联能够避免并发用户或重复任务造成混淆。

## 4.5 编辑、确认与版本冲突

读取事件得到当前版本后，再以该版本作为编辑或确认的依据。`expected_version_id`防止在旧页面上覆盖别人已经保存的新内容。冲突时重新读取并比较，不把同一请求无限重放到成功为止。

人工修改保存新版本；原版本与来源证据保留。确认针对当前版本进行。将`candidate`改成`confirmed`必须通过业务接口，不能直接更新数据库状态字段。

归档与来源追溯解决的是“这条记录怎么形成、谁确认了哪一版”。事件名称相近不代表同一设备，设备归属仍需第13章的人工身份关联。

## 4.6 从事件进入调查和工单

正式事件可以提交分类调查任务。系统创建`AgentRun`，按固定事件版本取证、判断经验适用性、评估风险和生成方案。结果形成待审核工作流，人工审核通过后才生成工单草稿。

工作流审核会检查事件版本和已确认观察的修订。调查完成后又补充了新事实，需要先核对或重做调查，不能用旧建议覆盖新事实。调查结构和工单流转见[第5章](第05章_异常分级与维检工单模块开发.md)。

巡检候选、隐患或其他事件也可以通过受控关联形成来源链。合并、替代与撤销保留历史关系，避免删除来源后失去解释依据。

## 4.7 验证方法

[事件与工单测试](../tests/test_event_and_work_order_flow.py)覆盖从抽取到审批的主流程；[调查测试](../tests/test_multi_agent_runtime.py)覆盖模型步骤和运行约束。重点检查：指定他人的来源版本、重复抽取、来源被编辑、旧版本确认、调查后再修改、任务取消和权限撤销。

模型质量另用人工标注样本评价。候选数量、成功HTTP响应和测试替身返回正确结构，都不能单独证明真实事件抽取准确率。
