# 第1章：项目技术与功能模块

API是客户端操作后端的接口；Worker是后台执行长任务的进程。Schema描述数据字段和约束，ORM把代码对象映射到数据库表，端口声明业务需要的外部能力。后文遇到新组件时，先理解它负责哪一步，再看怎样装配。

相关基础：[Web请求与服务](基础知识/01_Web接口与配置.md#t02)、[数据库与ORM](基础知识/02_数据库事务与迁移.md#t04)、[消息与后台任务](基础知识/03_任务权限与文件存储.md#t08)、[检索与模型](基础知识/05_检索文档与多模态.md#t23)、[部署与工程验证](基础知识/07_部署监控与工程验证.md#t35)。

## 1.1 项目解决什么问题

系统处理交接录音、生产异常、巡检图片、会议资料和企业规范，将它们连接到调查、整改和验收。模型承担转写、抽取、检索辅助及建议生成；业务服务保存版本、权限、审批和实测记录。

例如“阀门渗漏”可能先出现在交接录音里。转写和事件抽取产生候选，人员核对后形成正式事件。调查引用规范和历史经验，提出风险与处置建议；审核通过才生成工单，工单还要经过实际执行、复测和独立验收。

## 1.2 模块化单体与代码分层

模块化单体表示业务模块位于同一后端代码库、共享数据库与基础设施，但按职责分开组织。API和Worker可以分别部署进程，业务规则仍由同一套应用服务维护。

| 层 | 职责 | 阅读时关注 |
|---|---|---|
| `api` | HTTP/MCP参数、身份依赖、响应与业务入口 | 请求从哪里进入 |
| `application` | 用例、事务、状态变化、任务与模型编排 | 一次业务操作怎样完成 |
| `domain` | ORM实体、请求与结果Schema、领域规则 | 保存什么、输入输出受什么约束 |
| `ports` | 模型、存储、检索等能力契约 | 业务需要什么能力 |
| `infrastructure` | 外部协议、索引和Provider实现 | 怎样调用实际依赖 |
| `shared`、`bootstrap` | 身份、审计、任务、资源装配和配置 | 多个模块共同依赖的机制 |

应用层通过端口使用模型和存储；MCP与REST复用应用服务。只有存在实际依赖实现时才需要相应目录，不为分层形式创建空实现。

## 1.4 环境、Web与数据校验

项目使用Python 3.14。`uv`是环境与依赖管理工具，锁定依赖表示记录实际安装的版本组合；`pyproject.toml`声明项目要求，`uv.lock`记录实际解析版本；恢复环境使用`uv sync --frozen`。依赖、锁文件和构建的基本用法见[基础39](基础知识/07_部署监控与工程验证.md#t39)。

FastAPI将HTTP请求映射到函数，并依据类型和Pydantic模型校验输入、生成OpenAPI。Uvicorn负责监听端口并运行ASGI应用。依赖注入将数据库会话、当前用户和权限检查交给公共组件，具体业务函数接收已经解析的对象。

Pydantic是输入数据解析与校验工具，其模型描述接口或模型输出，不负责数据库持久化；SQLAlchemy模型描述数据库表。两者分开，才能明确区分“输入合法”与“业务操作获准”。例如UUID格式正确，不代表该工单属于调用者的数据范围。

## 1.5 数据与消息组件

| 组件 | 基本用途 | 项目中的数据 |
|---|---|---|
| PostgreSQL | 关系数据、约束和事务 | 业务状态、版本、权限、任务和审计 |
| SQLAlchemy、asyncpg | ORM与异步数据库访问 | 会话、查询、行锁和提交 |
| Alembic | 数据库结构版本 | 初始基线`0001`，后续`0002_agent_tasks`与`0003_station_locations` |
| RabbitMQ | 任务消息传递 | Worker待消费的任务消息 |
| Celery | 任务执行框架 | 任务注册、队列路由与Worker执行 |
| Redis | 快速共享状态 | Celery结果、限流等运行数据 |
| SeaweedFS S3 | 对象存储 | 音频、图片、文档和导出文件 |
| Elasticsearch | 全文检索 | 带版本标记的知识片段 |
| Qdrant | 向量检索 | 片段向量及过滤属性 |
| Neo4j | 关系与路径查询 | 文档事实图和业务关系投影 |

上述组件的入门分别见[PostgreSQL](基础知识/02_数据库事务与迁移.md#t05)、[SQLAlchemy](基础知识/02_数据库事务与迁移.md#t04)、[数据库驱动](基础知识/02_数据库事务与迁移.md#t06)、[Alembic](基础知识/02_数据库事务与迁移.md#t07)、[RabbitMQ](基础知识/03_任务权限与文件存储.md#t09)、[Redis](基础知识/03_任务权限与文件存储.md#t10)、[S3](基础知识/03_任务权限与文件存储.md#t14)、[Elasticsearch](基础知识/05_检索文档与多模态.md#t24)、[Qdrant](基础知识/05_检索文档与多模态.md#t25)及[Neo4j](基础知识/05_检索文档与多模态.md#t26)。

数据库记录与消息、索引不处于同一个跨系统事务。项目通过Outbox、可重试写入、完整快照发布和查询时复核保证业务边界，详见第2、8、13章。

## 1.6 模型能力与调查框架

文字模型默认使用百炼北京Qwen；ASR、视觉和知识运行时由项目专用服务提供。知识运行时承载文档解析、OCR、Embedding和Reranker。模型端口见[能力契约](../app/ports)，Provider装配见[providers.py](../app/bootstrap/providers.py)。

Embedding把文本表示为数值向量，用于语义召回；Reranker对问题与候选片段重新评分。ASR把语音转为文字；说话人分离只产生标签，姓名映射还需要人工确认。视觉模型返回图片候选，不自动确认隐患。

LangGraph用状态图连接任务节点；条件分支决定下一步，检查点把执行位置和状态持久化，便于恢复。详见[基础16](基础知识/04_智能体与专业流程.md#t16)。协调、取证、经验适用性、风险、方案与Critic分别承担不同问题；它们可以使用同一个文字模型。多角色的价值是职责、证据与复核过程可检查，不以调用模型的次数衡量复杂度。

MCP是AI客户端发现与调用服务能力的协议，工具可执行操作，资源提供可读取上下文，提示模板提供任务说明，见[基础18](基础知识/04_智能体与专业流程.md#t18)；内部调查使用只读工具注册表。MCP工具提交的观察也须先由人确认，才能进入事实上下文。

GEPA是提示词优化库，利用开发案例的运行轨迹提出新指令并比较效果，不训练模型权重。项目使用官方库组织搜索，评分、调用预算、人工验收和版本发布仍由原业务服务负责。概念与基本用法见[基础22](基础知识/04_智能体与专业流程.md#t22)，完整流程见[第11章](第11章_效果评测与改进验收闭环.md)。
