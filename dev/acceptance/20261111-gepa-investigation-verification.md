# 多步子调查与官方GEPA验证

子调查沿原AgentRun、AgentTask、证据和预算执行；提示词搜索使用官方GEPA 0.1.4，候选仍沿原提示词版本与改进验收发布。本次没有增加数据库表、迁移、容器服务或前端。

## 调查衔接

- 协调者为子问题指定完成条件与是否关键。分支先查询，再按证据决定换工具、换查询或结束；默认最多4次工具查询、4次决策、90秒，所有调用继续占用整次调查预算。
- 工具按问题类型限制，引用只能指向该分支当前有效证据。重复查询和局部步数上限停止分支；可选分支超时或上游服务失败保留缺口，不丢失其他分支成果。权限、取消和全局预算错误不降级为普通缺证。
- 分支结论、冲突和未知项汇入主调查，风险输出保留未解决缺口。关键分支缺证使用已有人工确认观察与恢复接口；恢复后的分支按新补证轮次执行，旧记录保留。
- 单个业务异常通过租约TaskGroup时保留原错误类型，预算冲突等可返回业务错误；非业务异常和多重异常保持原错误行为。

## 搜索与发布

官方引擎管理候选选择、接受和Pareto前沿，适配层提供原调查角色的执行、评分与Qwen反思调用。同步引擎在工作线程运行，数据库与模型操作留在原事件循环。生产依赖锁定GEPA版本与安装包哈希，没有引入另一套模型接口或密钥。

同一案例默认重复2次，记录每次输出、分数范围、逐题目标和相对基线的差值。本次搜索内对相同候选、案例的重复读取复用既有测量；新任务重新测量。任一次低估风险或引用越界均保留该缺陷，任一案例的此类退步不能被平均分提高抵消。结果记录是否保留基线；保留基线不代表效果提升。

候选建议标记为未经过安全复核，不沿用旧建议的可接受或不安全标签。格式错误记录为失败样本；预算、权限和系统服务故障中止任务。模型用量缺失时单独保留保守估计，取消后不再进入下一角色或生成版本。

发布仍要求不同开发事件的held_out完整调查、重新人工标注及已关闭改进验收，风险低估率与不安全建议率必须为0。发布记录保存之前的提示词版本；此前使用代码默认指令时先留存可回退版本。回退复用现有激活接口并记录原因，不改写历史调查。

## 验证结果

| 检查 | 结果 |
|---|---|
| 全量回归 | 233项通过，2项按配置跳过，覆盖率79% |
| 新增针对性用例 | 12项通过，已包含在全量统计中 |
| 静态检查 | Ruff、格式、mypy、编译和差异检查通过；依赖锁有效 |
| 文档 | 556个本地链接有效；40组基础概念保留；13段Python、7段JSON、8段Shell基础示例语法有效 |
| 运行接口 | 就绪200，224个HTTP操作，18个MCP工具；调查和优化新参数已出现在运行中接口契约 |
| 数据结构 | 85张应用表，迁移版本0003_station_locations |
| 部署 | API中GEPA为0.1.4，运行源码和依赖锁与工作区摘要一致；Worker、维护Worker、Beat及开发身份服务已更新 |

常规构建因基础镜像仓库连接超时未完成；本机部署使用已有项目镜像，按uv.lock校验GEPA安装包并同步完整生产依赖，依赖检查通过，再装入最终源码。仓库Dockerfile仍按冻结依赖构建。

本次没有宣称真实模型效果提高。搜索测试使用实际GEPA引擎和合成角色输出，证明选择、比较、取消、预算及发布约束；真实Qwen与专业标注案例仍需独立验证。气象接口在缺少站场位置时返回needs_location，外部气象和GIS数据未作真实验收。
